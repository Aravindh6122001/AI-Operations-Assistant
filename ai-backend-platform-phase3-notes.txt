AI BACKEND PLATFORM — QUICK PROJECT NOTES
============================================

COMMANDS TO KNOW FIRST
----------------------

Virtual environment
- Create: python3.12 -m venv venv
- Activate: source venv/bin/activate
- Deactivate: deactivate

Python / packages
- Check Python: python --version
- Install package: pip install <package>
- Install dependencies: pip install -r requirements.txt
- Save dependencies: pip freeze > requirements.txt

Run FastAPI
- Start server: uvicorn app.main:app --reload
- Start on a specific port: uvicorn app.main:app --reload --port 8000

Git
- Status: git status
- Add: git add .
- Commit: git commit -m "message"
- Push: git push origin main
- Log: git log --oneline

PostgreSQL / psql
- Connect: psql ai_backend
- List tables: \dt
- Describe table: \d table_name
- List indexes: \di
- Query: SELECT * FROM table_name;
- Explain query: EXPLAIN ANALYZE <query>;

Alembic
- Initialize: alembic init alembic
- Current migration: alembic current
- Create migration: alembic revision --autogenerate -m "message"
- Apply migrations: alembic upgrade head
- Roll back one migration: alembic downgrade -1
- Migration history: alembic history
- Mark current DB at migration: alembic stamp head


PROJECT QUICK MAP
-----------------

app/main.py
- FastAPI application
- Router registration
- CORS
- /health
- /db-health
- Global exception handler
- DO NOT use Base.metadata.create_all() once Alembic owns schema changes

app/api/
- HTTP endpoints / routes
- auth.py -> login/auth endpoints
- users.py -> user endpoints
- orders.py -> order endpoints
- product.py -> product endpoints

app/services/
- Business logic
- user_service.py -> user operations
- order_service.py -> order creation + transaction logic
- product_service.py -> product operations
- auth_service.py -> authentication flow

app/repositories/
- Database access/query layer
- user_repository.py -> User queries
- order_repository.py -> Order queries
- product_repository.py -> Product queries

app/models/
- SQLAlchemy database tables/models
- user.py -> users table
- order.py -> orders table + composite index
- order_item.py -> order_items table + foreign keys/indexes
- product.py -> products table + price/stock constraints

app/schemas/
- Pydantic request/response models
- users.py -> user create/update/response
- order.py -> order + order item request/response
- products.py -> product request/response
- auth.py -> authentication schemas

app/db/
- database.py -> SQLAlchemy engine + Base + connection/pool configuration
- session.py -> SessionLocal/get_db dependency

app/core/
- config.py -> .env/application settings
- security.py -> password hashing + JWT access/refresh tokens
- authentication.py -> authentication dependency
- authorization.py -> authorization/role checks

.env
- DATABASE_URL
- JWT_SECRET_KEY
- JWT_ALGORITHM
- ACCESS_TOKEN_EXPIRE_MINUTES
- REFRESH_TOKEN_EXPIRE_DAYS


POSTGRESQL / SQL — WHAT WE COVERED
-----------------------------------

Tables / relationships
- SQLAlchemy table definitions -> app/models/
- FK relationships -> order.py, order_item.py, user.py
- ORM relationship() -> app/models/order.py and user.py
- Order -> OrderItem one-to-many -> app/models/order.py + order_item.py

CRUD
- Create/read/update/delete -> app/repositories/ + app/services/ + app/api/

Transactions
- Transaction boundary / commit / rollback -> app/services/order_service.py
- Order creation + stock update happen in one transaction
- db.flush(), db.commit(), db.rollback(), db.refresh() -> order_service.py

Concurrency / row locking
- SELECT FOR UPDATE -> app/services/order_service.py
- SQLAlchemy: .with_for_update()
- Used when updating scarce stock concurrently

Relationships / eager loading
- relationship() -> app/models/order.py
- selectinload() -> repository/service query where relationship loading is needed
- Avoid N+1 queries by loading related rows efficiently

Indexes
- Single-column index -> app/models/ (mapped_column(index=True))
- Product name index -> app/models/product.py
- Order user/status indexes -> app/models/order.py
- OrderItem FK indexes -> app/models/order_item.py
- Composite index -> app/models/order.py
  Index("ix_orders_user_status", "user_id", "status")
- Manual SQL index:
  CREATE INDEX ...

Query optimization
- EXPLAIN ANALYZE -> PostgreSQL / psql
- SQLAlchemy builds the query; PostgreSQL query planner chooses the execution plan
- Look for Seq Scan / Index Scan in EXPLAIN ANALYZE output

Filtering
- SQLAlchemy .filter(...) -> app/repositories/
- Query parameters -> app/api/ + service/repository layer

Sorting
- SQLAlchemy .order_by(...) -> repository query
- Example: Order.id.desc()

Pagination
- limit()/offset() -> repository/service query
- API query parameters -> app/api/

Aggregation
- SQL COUNT/SUM/AVG/GROUP BY -> PostgreSQL queries
- SQLAlchemy aggregation functions -> repository layer
- No dedicated aggregation endpoint has been implemented yet

Constraints / data integrity
- Product price/stock CHECK constraints -> app/models/product.py
- Foreign keys -> app/models/
- unique/indexed user email -> app/models/user.py
- nullable/default settings -> models

Connection pooling
- SQLAlchemy engine -> app/db/database.py
- pool_size / max_overflow / pool_pre_ping / pool_recycle -> database.py
- Session lifecycle -> app/db/session.py

Alembic migrations
- Configuration -> alembic/env.py
- Migration config -> alembic.ini
- Migration files -> alembic/versions/
- Models imported into Alembic metadata -> alembic/env.py
- Autogenerate -> alembic revision --autogenerate
- Apply -> alembic upgrade head

JWT
